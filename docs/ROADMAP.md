> 状态：已定案执行（2026-09-02）
> 纪律：中文友好 · 不加版本号 · 只诊断不决策 · 诚实边界（不宣称推翻图灵/哥德尔）
> 关联：总架构 / 经典层详规 / 机制组合方案（内部规划文档，未随本仓库公开）

## 〇、目标（一句话）

paradox-engine 最终形态：**一个分情况分层、挂上 AI 就能用的逻辑建模引擎**——
经典逻辑打底（别人无门槛）、悖论/创生当发动机（独特卖点）、MT-MP-TL 当骨架、
冷门逻辑按场景选、AI 可调用；能处理复杂学科题目，也能让简单问题走轻量道；
撞到图灵机/哥德尔这类墙时，不假装能穿，而是"测墙→钻墙→看墙→换位→创生"。

## 一、最终分层架构

```
第 4 层  AI 挂载层        AI 可调用（工具/管线/协议）
第 3 层  冷门逻辑层       次协调 / Dung / 非单调 …（按痛点选）
第 2 层  悖论/创生层      悖论测度·注解·递归修正 · 对位创生（独创主场）
第 1 层  经典逻辑层       命题 → 谓词 → 时序 → 模态（地基，经典共识）
第 0 层  MT-MP-TL 骨架     点 / 线程 / 拓扑 / 操作（自有骨架）
```

### 阶段 1 · 第 1 层经典逻辑学基础（✅ 已完成 2026-09-06）
目标：把**经典逻辑学的基础全貌**做出来——不是几个判定器，而是按数学
逻辑标准四分法（语义判定 / 证明论 / 可计算性 / 类型与模型）覆盖地基。
这是建模的底子，也是给外人展示"这不是玄学"的证据。
> 每构件完整规格（管什么/算法/输入输出/验收/边界）见
> 内部规划文档《体系内部详规》（未随本仓库公开）。

**全景对照（为什么这些才算"基础"）**：

## 四、执行纪律（每阶段必守）

1. 每构件：机制形态（run→dict + PORTS + 自测）+ 中文注释 + 诚实拦截；
2. 每阶段：全量测试通过 + 更新开发进度记录（提交信息含测试数）；
3. 外部借鉴：标注来源 + 归"借鉴"区（不混原创区，落落三问纪律）；
4. 诚实边界：不宣称推翻图灵/哥德尔；不可判定=可诊断态非死胡同；
5. 中文友好：所有解释/输出中文；不加版本号。

## 五、风险与边界（诚实声明）

- 经典逻辑实现是"标准件"：网上有大量参考实现——我们的增量在
  **组合方式（撞墙管线/共振带收敛/对位创生）**，不在重造命题逻辑；
- 一阶逻辑半可判定：undetermined 是合法输出，不许硬截断；
- 对外展示：第 1 层证明"靠谱"（经典共识），第 2 层证明"独特"（落落独创）。

### 6.4 工作台线推进记录（2026-09-19）

「诊断工作台」姿态这条线，按需项已落地成一条能用的工作流（全程私下开发，未推远端）：

| 落地件 | 一句话 |
|:--|:--|
| 复核落笔 | `--mark S05 --verdict ok` 把复核结论写回场景表（只改 `checked`/`review` 两个字段），作者不必手改 Python |
| 多轮会话 | `--session 文件.json`：逐条材料累积诊断，跨命令记住前文（判类/复杂度/路由/五步结论/真跑构件） |
| 材料导入 | `--add-file 材料.md [--split para\|line]`：整篇材料逐段诊断记账；超限与空白段照实报，不静默截断 |
| 构件诊断落账 | 真跑过的构件记下 μ/grade/drill 等标量；撞墙管线跑出**五选一诊断**也进台账 |
| 复核依据进会话 | `--review --scene all` 把复核时的期望/实际/命中信号记进台账（**不**替作者改 `checked`） |
| 批次汇总 | `--overview`：按引擎自己的标签分组计数（判类/复杂度/置信度/构件状态/墙事件）——只统计，不做相似度聚类 |
| T5 对接 | `--revise "¬Q" --turn N` 把信念修正挂在第 N 条材料上；**引擎不抽公式**，命题式由人给 |
| 台账导出 | `--export 台账.md`：Markdown 报表（汇总/逐条/复核记录/修正史/边界），默认不覆盖已存在文件 |
| 端到端走查 | `engine/test_workshop_flow.py`：一条流程从材料到台账串起来测，全程不改场景表 |
| 线索建议 | `--suggest`：按实际路由列出每个构件要什么，能从原文指出来的给建议（带依据、标「是猜测」）；**不产生逻辑式、不替人估权重、不自动应用** |
| 线索落账 | `--add/--add-file ... --clues`：把建议记在轮次上；汇总按「可直接用 / 还欠人给 / 仍欠线索的轮次」统计 |
| 欠线索工作单 | `--pending [--pending-out 文件]`：待补轮次拼成可粘贴命令，欠的键留 `<待填>` 空位（引擎不猜值） |
| 复核看板 | `--review --board [--pending-only]`：一行一个场景，24 个待复核能排一屏（只读） |
| 复核进度快照 | `--progress`：记一次快照并与上次比「又复核了哪些 / 退回了哪些」 |
