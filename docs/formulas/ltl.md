# 公式卡：时序逻辑 LTL 构件（ltl）

> 概念来源：经典时序逻辑（LTL 标准语义）——非落落原创，经典共识
> 代码：engine/classical/ltl.py · 测试：engine/classical/test_ltl.py
> 本构件归第 1 层（经典地基层）：给"演化/过程/因果链"一个可判定的形式语言。

## 一、导言

命题/谓词回答"什么是真的"；LTL 回答"事情会怎样发展"。给一条状态路径
（系统随时间的状态序列），判定它是否满足时序性质——比如"系统永远不会
死锁""故障最终会恢复""恢复正常前一直告警"。

## 二、算子（经典 LTL）

| 算子 | 读法 | 含义（沿路径） |
|---|---|---|
| X φ | next | 下一状态满足 φ |
| G φ | globally | 所有（未来）状态满足 φ——"一直" |
| F φ | finally | 存在未来状态满足 φ——"最终" |
| φ U ψ | until | φ 一直成立直到 ψ 成立 |

原子命题 = 状态中的标记（如 {up, down}）；联结词 ¬ ∧ ∨ → ↔ 照常。

## 三、判定原理

沿路径递归求值：
- G φ：从当前位置扫到尾，全部满足则 holds，否则返回第一个违约位置；
- F φ：扫到第一个满足位置即 holds；有界路径扫完未满足 → violated（标注有界）；
- U：找 ψ 首次成立的 j，检查 [i,j) 间 φ 全真；φ 中途断 → 违约。

## 四、性质（P）

- P1 G 的违约可定位：violation_index = 首次不满足的位置（白箱）；
- P2 F 有界性：有界路径上 F 未满足 ≠ "永不"（诚实边界）；
- P3 U 语义：φ 必须坚持到 ψ 出现，中途断即违约；
- P4 复合：联结词与算子的任意组合（如 G(¬down) ∧ F(recovering)）。

## 五、公式（判定结构）

```
run({path, formula})
  ├─ 缺 formula → formula_pending
  ├─ 空 path → empty_path（至少需一个状态）
  ├─ 解析失败 → parse_error
  └─ 沿路径求值 → holds / violated(+violation_index)
```

## 六、注记与边界

- 状态用**稀疏集合**表示：{up} 表示 up 为真、其余未说 = 假——
  "¬正常 在 {down} 上为真"；
- **有界性诚实声明**：F(φ) 在有界路径未满足，输出"有界内未满足"而非
  "永不满足"——无穷路径的永不需无限观察（后续 Büchi 自动机版再处理）；
- 本构件是路径判定版，不含 CTL 路径量词（A/E——所有/存在路径）——
  那是系统级模型检测的扩展，后续构件；
- 语义全部经典 LTL（线性时间），不掺分支时间。
