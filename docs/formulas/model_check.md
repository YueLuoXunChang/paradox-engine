# 公式卡：CTL 模型检查（model_check）

> 概念来源：经典共识（Clarke–Emerson 1981 的 CTL 标记算法 / Pnueli 1977 时序逻辑）
> ——「给定有限状态图与初始状态，公式是否在所有可达行为上成立」是可判的，
> 而且算法简单到可以手写：不动点标记。
> 代码：engine/classical/model_check.py · 测试：engine/classical/test_model_check.py
> 本构件归第 1 层（经典地基层）：标准件，不掺私货。

## 一、导言

时序逻辑的 LTL 走"公式是否在所有路径上成立"，本构件走的是**模型检查**：
模型（一个显式的有限状态图）已经给定了，问式子在它上面成不成立。
这是工程验证的主力路线——**结论相对给定结构**，不是逻辑上的普遍有效。

## 二、判定原理

自底向上标记 + 不动点迭代：
- 把公式拆成子公式，从原子命题开始，逐层算出"哪些状态满足这个子公式"；
- 直到/存在算子用不动点迭代：`EG p` 取最大不动点（能一直走下去）、
  `AF p`/`AU` 取最小不动点（有限步内达到）；
- 最后看初始状态集合里的状态是否都在标记集合里。

## 三、性质（P）

- P1 不变式：互斥图（两进程不会同时进临界区）上 `AG !(c1 & c2)` 成立，
  `holds_in` 给出全部保持状态、`fails_in` 为空；
- P2 路径量词有区别：`EG p` 与 `AG p` 不是一回事——前者只要**存在一条**
  无限路径一路上 p 成立，后者要求所有路径；
- P3 必然/可能：`AF p` 与 `EF p` 的差别同上（一个要求所有路径最终 p，
  一个只要有一条路径能到 p）；`sat_count` 给出成立状态数；
- P4 死锁约定：无出边的状态上，全称算子（`AX`/`AG`）按"空集上真"处理，
  存在算子（`EX`/`EG`）为假——这是标准约定，写在边界里免得被当成 bug。

## 四、公式（判定结构）

```
run({states, transitions, labels, formula, init})
  ├─ holds_in ：公式成立的状态清单（含初始状态是否在内）
  ├─ fails_in ：不成立的状态清单（反例状态）
  ├─ sat_count：成立状态数
  └─ boundary ：相对结构的结论 + 死锁约定声明
支持写法：!/¬  & | ->  EX AX EF AF EG AG  E[p U q]  A[p U q]
```

## 五、注记与边界

- **只管 CTL**（路径量词 E/A 必须紧跟时态算子）：LTL 不在本构件，
  仍走 `ltl` 构件——本构件不假装能做自动机翻译；
- 状态图必须**有限且迁移闭合**：迁移里出现没声明的状态一律拦下（不隐式加状态）；
- 「成立」是**相对给定结构**的结论，**不是逻辑普遍有效**：换个结构可能就不成立；
- 这是与 `ltl` 互补的一条线：`ltl` 判路径公式，本构件在显式结构上做标记。
