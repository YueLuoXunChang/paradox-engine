# 公式卡：Kleene 递归定理（recursion_theorem）

> 概念来源：**外部经典共识**——Kleene 第二递归定理（1952）：对任意可计算函数 f，
> 存在程序 e 使得 φ_e = φ_{f(e)}（程序能拿到自己的代码并把它交给 f）。
> 归借鉴区（借数学底座，标注来源）。
> 代码：engine/classical/recursion_theorem.py · 测试：engine/classical/test_recursion_theorem.py
> 本构件归第 1 层（可计算性一侧）：**工程演示**，不是形式化证明。

## 一、导言

"自指"在计算里不是玄学，也不是悖论专属——递归定理说：**程序可以拿到自己的代码**。
本构件把这件事做成两个看得见的形态，与 λ 的 Y 组合子、图灵机的 UTM 自模拟
并置成"自指三形态"（函数层 / 执行层 / 代码层）。

## 二、判定原理

两个形态，各自可运行、可验证：
- **quine 形态**：用引号自指技巧构造"打印自身源码"的程序——自复制，
  自指最直观的形态；
- **递归定理形态**：对任意程序变换 f，构造自指程序 e——e 运行时先取自己的
  源码 s，算 f(s)，再执行 f(s) 的结果（行为 = f 作用后的自己，
  即 φ_e = φ_{f(e)} 的工程演示）。

## 三、性质（P）

- P1 quine 自复制：构造出的程序跑一遍，输出等于它自己的源码；
- P2 变换后仍自指：默认变换（给代码加一行注释）下，构造出的程序行为与原程序
  等价（φ_e = φ_{f(e)} 的可见形态）；
- P3 自指三形态对照：λ 的 Y（值不动点 Y f = f (Y f)）/ 图灵机 UTM（机模拟机）/
  本构件（程序读自己源码再变换）；
- P4 自指**不**解决不可判定：递归定理与停机问题并存——不宣称绕过定理。

## 四、公式（判定结构）

```
run({mode, payload, transform})
  ├─ mode='quine'     ：构造打印 payload 的 quine 程序 → constructed
  ├─ mode='recursive' ：构造"取自己源码 → f(源码) → 执行"的程序 → verified
  └─ 输出：program（构造出的源码）+ runs_like（运行行为说明）
诚实拦截：需要超出"单行无引号简单源码"时如实拦下（引号技巧对多行/特殊字符敏感）
```

## 五、注记与边界

- 这是递归定理思想的**工程演示**（Python 引号自指技巧），**不是形式化证明**：
  形式化的部分在 λ 演算与图灵机两个构件里（1.6 / 1.7 已代码化）；
- 输入限**单行、无引号**的简单源码——诚实限制，不假装能吃任意程序；
- **自指 ≠ 绕墙**：本构件演示的是"程序能拿自己"，不是"自指能判定停机"；
  停机不可判定仍成立（见 turing_machine 构件与可判定片段地图）；
- 借来的东西归借鉴区：本卡与代码 docstring 都写明出处。
